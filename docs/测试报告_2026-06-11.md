## 四、发现并修复的缺陷

测试共暴露 7 个缺陷，按严重程度排列。所有修复均已部署生产环境并复测通过。

### 缺陷 1（致命）：共享密钥用户看到的是假演示而非真实生成

- **现象**：使用内置模型生成时，界面播放一段 26 秒的脚本化演示内容（固定话题、固定文案），并非真实模型输出；生成结果不入库。
- **根因**：实时模式判定只认「客户端配置了 Key」一种情况，走服务端共享密钥的请求被错误降级到演示时间线。
- **修复**：实时模式判定改为「客户端有 Key 或模型支持服务端密钥通道」。（commit `4b3c56d`）

### 缺陷 2（致命）：服务端共享密钥地址兼容性不足，请求 404/401

- **现象**：生成请求到达上游模型服务后返回 404 或 401。
- **根因**：环境变量中填写的上游地址带有面向另一类客户端的路径后缀，且版本段缺失时无容错；密钥值的首尾空白也未清理。
- **修复**：服务端代理增加地址归一化——自动剥离多余路径后缀、自动补全版本段、去除首尾空白，管理员在配置时无需关心地址的细微格式差异。（commits `8dede14`、`c4c5fd7`）

### 缺陷 3（致命）：推理类模型正文为空（「写完了，共 0 字」）

- **现象**：生成流程正常走完，但报告字数为 0。
- **根因**：内置模型属于推理类模型，思考过程消耗了全部 token 配额，正文流为空。
- **修复**：服务端代理对该类模型自动关闭思考模式，token 全部用于正文输出。复测确认推理 token 为 0、正文完整。（commit `bea2e6b`）

### 缺陷 4（严重）：实时保存路径引用了未导入的校验函数，生成报错

- **现象**：真实生成完成时前端抛出 `validateReport is not defined`。
- **根因**：校验函数定义在工具模块内但未导出，主应用也未导入；此前该代码路径从未被真实生成触发过，缺陷一直隐藏。
- **修复**：导出并正确导入该函数，本地构建验证后上线。（commits `3f7871b`、`aac7e1c`）

### 缺陷 5（一般）：头像菜单显示硬编码邮箱

- **现象**：任何账号登录后，头像菜单都显示开发者本人的邮箱。
- **修复**：改为读取当前登录用户的资料邮箱，缺失时回退到会话邮箱。（commit `4b3c56d`）

### 缺陷 6（一般）：引用面板出现空白条目

- **现象**：报告未返回结构化引用时，引用面板渲染出只有分隔符的空行。
- **修复**：增加回退文案，标题、链接、日期均改为有值才渲染。（commit `4b3c56d`）

### 缺陷 7（轻微）：误报「报告未以标题开头」

- **现象**：报告带有标准标题标记且内容正常，顶部仍出现黄色格式警告。
- **根因**：校验规则只认 Markdown 井号标题，不认应用自有的标题标记格式。
- **修复**：校验规则放宽——存在标题标记即视为有标题。复测警告消失。（commit `92513fc`）

### 附带修复：新用户默认模型不生效

- 旧逻辑硬编码了默认模型 ID，使「优先选择内置免配置模型」的回退逻辑永远不可达；改为空初值后回退逻辑生效。（commits `1005eca`、`b1dc085`）

## 五、关键验证留痕

1. **真实性验证**：缺陷 1 的定性依据——「生成」内容与代码内置演示文案逐字一致，且本地存储无新增报告记录；修复后内容随提示词变化、接口有真实流式响应。
2. **接口层验证**：浏览器内直调 `/api/generate`（携带登录态），修复前后分别捕获 401/404 错误体与 200 流式响应，错误体中的上游特征用于定位地址配置问题。
3. **上游交叉验证**：用 curl 携带无效密钥直连上游服务，比对错误格式，排除了认证头格式问题，把问题面收敛到地址与密钥值本身。
4. **最终复测**：两次完整界面生成（38.2 秒 / 2526 字、46.0 秒 / 2523 字），报告页、目录、引用面板、字数与 token 统计全部正常，无任何警告横幅。

## 六、遗留事项与建议

| 事项 | 级别 | 建议 |
|---|---|---|
| 测试账号清理 | 低 | 测试完成后可在数据库后台删除本次注册的测试账号 |
| 主应用单文件过大（700KB+ 源码） | 技术债 | 后续按模块拆分，降低回归风险 |
| 推理模式开关 | 优化 | 目前对内置模型固定关闭思考模式；如未来希望利用推理能力提升报告质量，可做成可配置项并相应放大 token 上限 |
